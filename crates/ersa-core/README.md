# ersa-core

The library that is Ersa's Core: sessions and their projection from the backend's session record and live stream, the in-memory raw log, the app log, the adapter registry, transports, workspaces and VCS, packs, modes, the harness tools server, and persistence. The `ersa-core` binary in `ersa-cli` is a thin wrapper around it, and the same binary runs on remote hosts. It must never depend on Tauri or anything that needs a window or display, so it builds and tests on a headless machine. Code that only works on one operating system belongs behind the narrow `platform` module (named pipes and their security descriptor on Windows, a Unix socket stub elsewhere), and `tests/boundaries.rs` checks both rules. `Server::bind` then `Server::run` is the Core process: the Core API server in `api`, the SQLite database with its migrations in `persistence`, and git worktrees run through the transport in `workspace`. `tests/core_api.rs` and `tests/workspaces.rs` drive a real server over its socket.
