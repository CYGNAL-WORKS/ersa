# Title

## Purpose

What the component is for and when to use it rather than a neighbour.

## Anatomy

The named parts, in a list. Names become identifiers, so use glossary terms.

- **part**: what it is.

## States

Every state the component can be in, one line each. Include loading, empty, error, disabled, and focus where they apply.

## Variants

Named variants and what distinguishes them. Variants are visual; states are behavioural.

## Behaviour

What the component does on each input: click, keyboard, drag, external data change. Include timing where it matters.

## Content

What text or data it displays, limits, truncation, and formatting rules.

## Accessibility

Role, name, keyboard operation, and what screen readers announce on state change.

## Tokens

The design tokens this component consumes, by token name. No raw values.
