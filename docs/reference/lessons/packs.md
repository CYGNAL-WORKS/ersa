# Packs: lessons for later

- **Where packs install.** ARCH-CORE renders a pack into the project's own files. The alternative is installing each pack once, app-wide, as a plugin folder passed by path (`--plugin-dir`, `pluginDirectories`); Claude Code 2.1.282 and Copilot 1.0.88 both load a whole pack from one Claude-layout folder. This is likely an ADR, and bears on FLOW-APPLY-PACK's open question on tracked files. Whether the Rust SDK reaches `pluginDirectories` is unchecked.
- **Command-line limits and secrets.** Command lines cap at 32,767 characters, or 8,191 through a `.cmd` shim, which holds about 60 plugin folders. Secrets in arguments show in process listings, so pass MCP secrets as `${VAR:-}` references filled from the environment.
- **Backend differences.** For FLOW-APPLY-PACK's open questions on backends and the schema: agent tool names differ per backend, so each backend gets its own rendering; Copilot on Windows silently strips `Bash` and `PowerShell` from project custom agents; a pack's hooks are safest never imported or run.
- **Publishing.** For the open question on verifying packs from HTTP sources: make published versions immutable, enforced by server permissions, and avoid a shared index file for publishers to race on. That needs a server that can list what it holds; a plain HTTP source would still need some listing.
