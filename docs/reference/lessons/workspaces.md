# Workspaces: lessons for later

- **Reclaiming abandoned workspaces.** Every session gets a workspace (FLOW-NEW-SESSION-R04) and only `workspace.remove` deletes one; whether Ersa reclaims abandoned ones is undecided, and likely an ADR. A sweep that has worked: run on a standing interval after every session has declared its hold, log why each worktree is kept, and keep anything uncertain. Reclaim a worktree whose work is pushed, merged, or held by another ref, whose upstream is gone, that has no commits of its own, or that sat idle past a grace period. Sort outside the lock and remove under it; sorting fifty under the lock stalled worktree creation past timeouts.
- **Removing one.** ARCH-CORE's "stop-then-remove with retry" doesn't match the code, which keeps the branch, refuses a folder git doesn't list, and stops nothing (it retries, and `workspace.remove` is refused while sessions exist). The brief should state that, and say what happens to other processes rooted in the folder, such as terminal-pane shells: stop every process whose working directory or executable is inside it, except Ersa itself.
- **Default base.** `workspace.create`'s `base` has no stated default; the code uses the repository's `HEAD`, the root checkout's current branch. The alternative is the mainline: `origin/HEAD`, then `origin/main` or `master`, then local `main` or `master`, and only then the current branch. FLOW-NEW-SESSION's controls are a second home for the answer.
